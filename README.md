# 相互レビュー

個人開発のアプリを、開発者どうしが対等に見せ合う場所です。お金は使いません。

## しくみ

1. **依頼する。** 「Issues → New issue → レビューを依頼する」から、自分のアプリと見てほしい点を書きます。券を1枚使います（最初の1枚は配られています）
2. **割り当てられる。** 係が、手の空いている参加者を1人選んで頼みます。依頼した人が直前にレビューした相手には頼みません（お返しの褒め合いを防ぐため）
3. **引き受けるか、見送る。** 頼まれた人は `/take` か `/pass 理由` と書きます。見送っても何も減りません。返事がないと3日で次の人に回ります。3人に見送られた依頼は、券を返して閉じます（重い依頼は自然に後回しになります）
4. **レビューする。** 引き受けた人は7日以内に、決まった型で `/done 人`（または `AI`、`人+AI`）から始まるコメントを書きます
5. **受け取る。** 依頼した人が `/helpful`（役に立った）か `/not-helpful` を書きます。役に立ったレビューを書いた人に、券が1枚入ります。7日返事がなければ「役に立った」で閉じます

いつでも `/tickets` と書けば、自分の券の数がわかります。

## 決まり

| 決まり | 理由 |
|---|---|
| 作られてから90日以上たったGitHubのアカウントで参加 | 使い捨てのアカウントで券を集めるのを防ぐ |
| 依頼できるのは、自分のアカウントのリポジトリだけ | 作り手であることの確認 |
| 書いた人（人 / AI / 人+AI）を必ず書く | AIだけのレビューも歓迎。ただし券は増えない（ほぼ手間がかからないので、人の作業と同じ1枚にはしない） |
| アプリストアの星や、宣伝用の推薦文の交換はしない | ストアの決まりと、ステルスマーケティングの規制に触れるため |
| 画面の写真に、アドレス・残高・個人情報を写さない | 安全のため |

決まりの数値は `data/rules.json` にあります。ジャンルを足すときも、このファイルに1つ書き足すだけです。

## 記録

すべての出来事は `data/ledger.jsonl` に1行ずつ残ります。券の数はこの記録から数え直すので、だれも勝手に増やせません。レビューの本文は記録せず、本文の指紋（ハッシュ）だけを残します。将来チェーンに載せるときは、この記録をそのまま写します。

---

**English (short):** Developers review each other's apps as equals. Spend 1 ticket to request a review; earn 1 when your review is marked helpful. Assignment avoids direct favor-swapping, passing is free, and every event is kept in an append-only ledger. AI-only reviews are welcome but don't earn tickets.
